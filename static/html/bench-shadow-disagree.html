In the MVG 'push gradient' handler, upstream guards this copy with `((q-p+4+1) > MagickPathExtent)` so the copied gradient-definition substring cannot exceed MagickPathExtent. That bounds check was deleted (only `(q-4) < p` remains), so the length `q-p-4+1`, fully controlled by the distance between the attacker-supplied 'push gradient' and matching 'pop gradient' tokens in the MVG/DRW input, is passed unchecked to CopyMagickString. With the size-cap removed the gradient body length is no longer validated before being copied into the parser token buffer, reintroducing the classic gradient-definition buffer overflow that this check exists to prevent. Reachable from any untrusted .mvg/SVG/-draw input.
